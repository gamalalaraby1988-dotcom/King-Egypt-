# تجهيز بيئة Supabase مجانية للاختبار — KING OF EGYPT CITY

**الحالة:** خطة تجهيز آمنة؛ لم يتم إنشاء مشروع Supabase أو نشر قاعدة بيانات أو API بعد.  
**القرار:** Supabase مرشح أول لبيئة التطوير والاختبار فقط، مع PostgreSQL.  
**الفرع:** `supabase-free-test-environment`  
**التاريخ:** 13 نوفمبر 2026

## 1. حدود البيئة

- مشروع Supabase مستقل باسم تطوير/اختبار، منفصل تمامًا عن أي بيئة إنتاج مستقبلية.
- استخدام الخطة المجانية فقط، وعدم تفعيل أي ترقية مدفوعة أو إضافة مدفوعة.
- بيانات اصطناعية بالكامل وحسابات اختبار يملكها فريق التطوير؛ لا تُرفع بيانات لاعبين حقيقيين أو كلمات مرورهم أو أرصدتهم أو سجلاتهم.
- لا تُستورد ملفات الحفظ المحلية للاعبين ولا تُجرى أي عملية ترحيل في هذه المرحلة.
- لا تغييرات في أسعار اللعبة أو المكافآت أو الأرصدة أو الملكيات أو قواعد الاقتصاد المعتمدة.
- لا توضع مفاتيح أو أسرار أو كلمات مرور في Git أو ملفات المشروع أو المحادثة.

## 2. ما يلزم قبل إنشاء المشروع

1. توصيل حساب Supabase من خلال تكامل Supabase في ChatGPT.
2. التأكد من أن الحساب يملك صلاحية إنشاء مشروع جديد.
3. إنشاء مشروع اختبار مستقل على الخطة المجانية فقط.
4. اختيار أقرب منطقة استضافة مناسبة ومتاحة للحساب بعد مراجعة الخيارات الظاهرة في لوحة Supabase؛ لا يُثبت اختيار المنطقة قبل التأكد من توفرها وقياس زمن الاستجابة.
5. الاحتفاظ بكلمة مرور قاعدة البيانات والمفاتيح السرية في مدير أسرار آمن خارج المستودع.

**لا تنشئ المشروع باسم الإنتاج ولا تستخدم مشروعًا قائمًا يحوي بيانات حقيقية.**

## 3. فصل المفاتيح والصلاحيات

- مفتاح العميل القابل للنشر (publishable/anon بحسب واجهة Supabase) ليس بديلًا عن المصادقة أو سياسات RLS.
- مفتاح `service_role` أو أي مفتاح سري لا يوضع مطلقًا داخل Godot أو APK أو Git أو جهاز اللاعب.
- لا تمنح العميل صلاحية كتابة مباشرة في جداول الأرصدة أو دفتر المعاملات أو الملكيات.
- تظل عمليات الاقتصاد الحساسة خاضعة لعمليات خادمية موثوقة، والتحقق من جلسة المستخدم، وقيود قاعدة البيانات، والمعاملات الذرية، ومنع التكرار.
- تفعيل RLS على الجداول التي يمكن الوصول إليها من واجهة API، واختبار الرفض الافتراضي قبل السماح بأي وصول.

## 4. نطاق الاختبار الأولي

بعد إنشاء المشروع وربطه، يبدأ الاختبار على بيانات اصطناعية فقط، وبالتدرج التالي:

1. التأكد من اتصال المشروع وقاعدة PostgreSQL.
2. إنشاء حسابات اختبار غير حقيقية والتحقق من دورة تسجيل الدخول والخروج.
3. اختبار سياسات RLS بحسابين اصطناعيين منفصلين، والتحقق من عدم قدرة أحدهما على قراءة أو تعديل بيانات الآخر.
4. اختبار دوال قاعدة البيانات بمعاملات وهمية معزولة، تشمل نجاح العملية، رفضها، التزامن، إعادة إرسال الطلب، ومفتاح منع التكرار.
5. التحقق من أن فشل العملية لا يترك خصمًا أو إضافة جزئية.
6. حفظ سجلات الاختبار ونتائجها دون إدخال أي بيانات شخصية حقيقية.

لا تُنفّذ عمليات شراء أو مكافآت أو تحويلات حقيقية في هذه البيئة، ولا تُعتمد أي قيمة اقتصادية جديدة ضمن هذه الخطوة.

## 5. بوابة قبل ربط Godot

لا يُربط عميل Godot حتى تتحقق جميع النقاط التالية:

- توثيق مخطط قاعدة البيانات وسياسات RLS ودوال العمليات.
- إثبات أن هوية اللاعب تستخرج من جلسة مصادق عليها ولا يرسل العميل هوية يختارها لتغيير الاقتصاد.
- إثبات أن الأسعار والمبالغ والمكافآت تُحدد على الخادم، لا من مدخلات العميل.
- إثبات الذرية ومنع التكرار وسلامة الطلبات المتزامنة.
- إثبات عدم تسرب المفاتيح السرية إلى العميل أو ملفات التصدير.
- اجتياز اختبارات العزل والصلاحيات والفشل والتكرار.
- مراجعة التوافق مع عقد خدمة الاقتصاد `docs/ECONOMY_SERVER_API_CONTRACT_AR.md` وخطة الترحيل الآمنة.

## 6. حدود ما لم يُنفذ

هذه الوثيقة لا تعني أن مشروع Supabase قد أُنشئ، أو أن قاعدة بيانات أو Auth أو Edge Function أو RPC قد نُشرت. كما لا تثبت وجود خادم لعب جماعي لحظي. لا يزال اختيار وتنفيذ خدمة اللعب اللحظي، إن تطلبها تصميم اللعب الجماعي، قرارًا منفصلًا بعد فحص متطلبات الاتصال والأداء.

لا يُعد أي اختبار في لوحة Supabase وحده إثباتًا لتكامل اللعبة أو جاهزيتها للإطلاق. يلزم لاحقًا اختبار التكامل من عميل Godot وعلى Android فعلي.

## 7. ضوابط التكلفة

- البقاء على الخطة المجانية طوال مرحلة التحقق.
- عدم تفعيل أي إضافة أو مورد مدفوع.
- مراقبة حدود الاستخدام والتنبيهات المتاحة في لوحة المشروع.
- مراعاة أن المشاريع المجانية قد تتوقف مؤقتًا بعد فترة من عدم النشاط؛ لا تُعامل هذه البيئة كخدمة إنتاج أو كضمان توافر.
- إذا اقترب الاستخدام من حد مجاني أو تطلبت خطوة ترقية مدفوعة، تتوقف الخطوة ويُطلب قرار صريح قبل أي تكلفة.

## 8. معيار إتمام مرحلة التجهيز

تُعد مرحلة التجهيز مكتملة فقط بعد إنشاء مشروع الاختبار المجاني فعليًا، وتأكيد المنطقة والخطة، والتحقق من صلاحيات الوصول، وتشغيل اختبارات الاتصال والأمان الاصطناعية، وتوثيق نتائجها. وحتى ذلك الحين تظل الحالة: **بانتظار توصيل حساب Supabase وإنشاء مشروع اختبار منفصل**.
