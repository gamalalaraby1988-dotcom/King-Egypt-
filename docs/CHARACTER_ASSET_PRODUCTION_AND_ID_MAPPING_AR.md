# مواصفات إنتاج وربط أصول الشخصيات الـ16
## KING OF EGYPT CITY

### الغرض والنطاق
هذا المستند يحوّل كتالوج الشخصيات المقترح إلى قائمة أصول قابلة للتسليم والربط داخل اللعبة. يثبت المعرفات التقنية أدناه حتى لا تتغير عند استبدال النماذج المؤقتة بالأصول النهائية.

هذا **ليس** إثباتًا أن النماذج النهائية أُنتجت. لا توجد حاليًا أصول 3D نهائية موثقة في المستودع. لا تُستخدم صورة اختيار الشخصيات المولدة كبديل عن نموذج 3D أو ملف Rig.

### الهوية الفنية المشتركة
- نماذج ثلاثية الأبعاد شبه واقعية بلمسة فنية راقية، ضمن الهوية المصرية الملكية المعاصرة للمدينة.
- جميع الشخصيات الست عشرة على مستوى جودة موحد: النحت، الخامات، الإضاءة، الـRig، التحريك والتعبيرات.
- شخصيات جاهزة ومتكاملة؛ لا خزانة أزياء، ولا تخصيص مستقل للملابس أو الشعر أو الجسم، ولا تبديل ألوان.
- لا تُستخدم ملابس أو ملامح نمطية تختزل ثقافة الشخصية. الجنسية مرجع تصميمي محترم وليست قالبًا شكليًا.
- مراعاة Android: ميزانيات مضلعات وخامات مناسبة، LOD، ضغط textures، skeleton مشترك متوافق حيثما أمكن، وتحميل الأصول عند الحاجة.
- اتجاه أمامي موحد، مقياس موحد، نقطة أصل عند القدمين، وارتفاع مرجعي موحد لتسهيل تبديل الشخصية.

### حزمة التسليم المطلوبة لكل شخصية
1. ملف المصدر القابل للتحرير من أداة النمذجة، مع بيان الإصدار.
2. نموذج 3D مُصدّر إلى صيغة مناسبة للاستيراد في Godot، ومشهد Godot مستقل بالمسار المحدد.
3. هيكل عظمي متوافق مع معيار المشروع، مع Idle / Walk / Run / Sit، وتعبيرات الوجه الأساسية إن كانت ضمن الـRig.
4. خامات ومواد PBR مضبوطة للأداء، مع نسخ textures مضغوطة ومقاسات موثقة.
5. صورة بطاقة اختيار واضحة، وصورة معاينة أمامية وخلفية؛ الصور لا تحل محل النموذج.
6. تقرير فني قصير: عدد المضلعات، عدد المواد، أحجام textures، عدد العظام، أحجام الملفات، ونتيجة فحص الاستيراد.
7. مراجعة فنية وثقافية قبل اعتماد الأصل.

### معايير القبول
- تحميل المشهد دون أخطاء أو مراجع مفقودة.
- ظهور الشخصية كاملة في معاينة الاختيار، ثم داخل العالم، بنفس المقياس والاتجاه.
- نجاح الأنيميشن الأساسية وعدم وجود تشوهات واضحة في المفاصل.
- عدم تداخل أجزاء الجسم أو الخامات، وعدم وجود ملفات مصدر/خامات مفقودة.
- أداء مقبول على جهاز Android المستهدف بعد قياس فعلي؛ لا يُعلن النجاح دون اختبار.
- تطابق أصل الشخصية مع ID واحد فقط في الكتالوج.

### الربط داخل اللعبة والحفظ
- كتالوج مركزي يربط ID الثابت بالاسم والبلد والنوع ومسار المشهد وصورة البطاقة.
- اختيار اللاعب يُحفظ عبر خدمة الملف الشخصي على الخادم، في الحقل selected_character_id، بعد التحقق من أهلية الاختيار.
- لا يُقبل مسار مشهد أو ID يرسله العميل باعتباره موثوقًا؛ الخادم يتحقق من ID المسموح به.
- لا يُخزن الاختيار باعتباره تقدمًا محليًا مستقلًا، ولا يؤدي تبديل الشخصية إلى تصفير المستوى أو XP أو الأصدقاء أو الممتلكات.
- لا تُفعّل عملية شراء أو خصم أو قيمة Cash/Gems من هذه المواصفات. أي إتاحة مدفوعة تبقى معطلة حتى اعتماد الاقتصاد الموحد صراحةً.

### الحالة الحالية
- المعرفات ومسارات التسليم: محددة في هذا المستند.
- ملفات النماذج النهائية والـRig والخامات: **لم تُسلّم ولم تُتحقق بعد**.
- ربط الـ16 أصلًا النهائي داخل مشهد اللعبة: **غير منفذ**.
- حفظ selected_character_id على الخادم: **تصميمه موثق سابقًا، لكن لا يُعد منفذًا أو مختبرًا هنا**.
- اختبار Android: **لم يُجرَ ضمن هذا التحديث**.

### ما لا يدخل في هذه المرحلة
لا خزانة أزياء، لا تغيير ألوان أو ملابس، لا متجر أزياء، لا أسعار، لا خصم عملات، ولا تعديل حساب المؤسس.
