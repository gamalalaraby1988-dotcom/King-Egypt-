# خطة فصل إعدادات بيئات البناء — KING OF EGYPT CITY

**التاريخ:** 2026-11-25  
**الفرع:** `integration/safe-mainline-audit`  
**الحالة:** خطة تنفيذ ومراجعة فقط؛ لم تُغيّر ملفات المشروع التشغيلية.

## 1) الوضع الذي تم التحقق منه

- `main/project.godot` يحدد `auth/api_base_url` و`auth/publishable_key` لمشروع Supabase PRODUCTION.
- `staging/email-auth-session/project.godot` يحدد القيم نفسها لمشروع Supabase TEST.
- PR #156 يستهدف `main`، ويغيّر هذين الإعدادين إلى TEST. هذا التغيير يجب ألا يصل إلى إصدار الإنتاج.
- `export_presets.cfg` الحالي يحتوي preset Android واحدًا باسم Android ومسار APK باسم debug. لا يوجد فصل موثق بين preset اختبار وpreset إنتاج في الملف الذي تمت مراجعته.

## 2) التصميم المقترح

### مصدر الإعدادات

إنشاء إعداد تشغيل واحد واضح يقرأ القيم من ملف إعداد بيئة مخصص أو من إعدادات البناء الممررة وقت التصدير، بدل نسخ عنوان المشروع ومفتاحه بين فروع Git.

الحقول المطلوبة:
- `environment_name`: إحدى القيمتين `test` أو `production`.
- `supabase_url`: عنوان المشروع الموافق للبيئة.
- `supabase_publishable_key`: المفتاح العام القابل للنشر الخاص بالمشروع نفسه.
- `auth_redirect_uri`: `kingofegyptcity://auth-callback` بعد تسجيله في كل بيئة مطلوبة.

مفتاح Supabase publishable ليس service-role key ولا يمنح صلاحيات إدارية بمفرده؛ مع ذلك يجب إبقاء كل إصدار مربوطًا بمشروعه الصحيح، والاعتماد على RLS وسياسات الخادم لحماية البيانات. يمنع تضمين service-role key أو أي مفتاح توقيع خاص في عميل اللعبة أو مستودع Git.

### ملفات البيئة

- ملف إعداد TEST مخصص لبناءات الاختبار فقط.
- ملف إعداد PRODUCTION مخصص لإصدارات الإنتاج.
- لا تضع قيمًا سرية في أي منهما. يمكن أن يحتوي الملفان على عنوان المشروع ومفتاح publishable العام.
- لا تجعل التطبيق يختار البيئة اعتمادًا على اسم المستخدم أو قيمة يرسلها اللاعب.
- إذا تعذر تمرير إعدادات التصدير بشكل آمن وموثوق في Godot، استخدم ملف إعداد منفصلًا يختاره مسار CI صراحةً، مع تحقق آلي من محتواه قبل التصدير.

### مسارات البناء

| المسار | الإعداد المسموح | مخرجات مقترحة |
|---|---|---|
| اختبار/QA | TEST فقط | APK باسم `KING_OF_EGYPT_CITY-TEST-debug.apk` |
| إنتاج/Release | PRODUCTION فقط | APK/AAB إصدار إنتاج موقّع |

يجب أن تكون مفاتيح توقيع Android محفوظة في GitHub Actions secrets أو مخزن أسرار معتمد، لا داخل المستودع ولا في ملفات إعداد العميل.

## 3) بوابات CI المطلوبة قبل التصدير

1. يفشل بناء TEST إذا لم يطابق `environment_name=test` وعنوان TEST المعروف.
2. يفشل بناء PRODUCTION إذا لم يطابق `environment_name=production` وعنوان PRODUCTION المعروف.
3. يفشل بناء PRODUCTION إذا احتوى أي ملف/إعداد محمّل على عنوان TEST.
4. يفشل البناء إذا كان `supabase_url` أو `supabase_publishable_key` فارغًا أو غير متطابقين مع البيئة المحددة.
5. يتحقق الاختبار من أن `auth_redirect_uri` مسجل لدى مزود Auth لكل بيئة.
6. يتحقق من عدم وجود service-role key أو private signing key أو Android signing material ضمن ملفات التتبع في Git.
7. يطبع سجل البناء اسم البيئة ومعرّف المشروع غير السري فقط، ولا يطبع أي أسرار.

## 4) التعامل مع PR #156

- لا تدمج PR #156 بصورته الحالية؛ لأن تغيير `project.godot` فيه ينقل إعداد TEST إلى main.
- احتفظ بميزة تسجيل الدخول بالبريد وكلمة المرور منفصلة عن اختيار بيئة Supabase.
- قبل إعادة تقديم التغيير: اجعل إعداد البيئة يأتي من مسار البناء، وأبقِ Google OAuth كمسار بديل للحسابات المرتبطة كما هو مقصود.
- لا تغيّر حسابات اللاعبين أو كلمات المرور أو إعدادات Auth خلال إصلاح فصل البيئات.

## 5) اختبارات قبول مطلوبة

- بناء TEST يتصل حصريًا بمشروع TEST؛ وبناء PRODUCTION يتصل حصريًا بمشروع PRODUCTION.
- محاولة بناء إنتاج مع ملف TEST يجب أن تفشل قبل إنشاء APK/AAB.
- تسجيل الدخول بالبريد، وGoogle OAuth، وcallback، وrefresh token تُختبر في TEST أولًا.
- التحقق من عدم اختلاط بيانات TEST وPRODUCTION باختبارات حسابين منفصلين.
- اختبار Android فعلي لتخزين الجلسة واستعادتها وتسجيل الخروج وتبديل الحساب.
- اختبار إصدار إنتاج تجريبي قبل النشر العام، مع التحقق من توقيع الحزمة واسمها وإعدادات redirect.

## 6) حدود التنفيذ الحالي

هذا الملف خطة مراجعة فقط. لم يتم:
- تعديل `project.godot` أو `export_presets.cfg` أو ملفات CI.
- إنشاء ملفات بيئة أو إضافة أسرار إلى GitHub.
- تغيير إعدادات Supabase أو نشر وظائف.
- تعديل PR #156 أو دمجه.
- إنشاء APK/AAB أو توقيعه.

**القرار الآمن الحالي:** إبقاء `main` على إعداد PRODUCTION كما هو، واعتبار PR #156 غير جاهز للدمج حتى يمر فصل البيئات واختبارات القبول أعلاه.
